# Phase 0 技術検証: 学習指導要領に基づく問題自動生成の実現可能性

対応Issue: #2

## 背景
KodoPace の中核機能である「学習指導要領に基づいた実力測定問題の生成」と
「解答結果を元にした個別最適化問題の生成」が、AI(Claude等)で実現可能かを検証する。

## 検証方法
文部科学省 小学校学習指導要領(国語・算数)の学年別内容(単元、到達目標、漢字配当表など)を
プロンプトに明示的にインプットし、以下を確認した。

1. 国語・算数それぞれで学年別サンプル問題セットが生成できるか
2. 生成された問題の正答率・難易度が学年水準として妥当か
3. 誤答傾向から苦手分野を分析し、類題を再生成できるか
4. プロンプト設計のみで十分か、RAG(教科書/指導要領データの参照)が必要か
5. 同じ学年でも1学期・2学期・3学期など時期によって学習内容が異なることに対応できるか

検証に使用したプロンプトテンプレートは [`prompts/`](./prompts) に、
生成されたサンプル問題は [`samples/`](./samples) に格納している。

## 検証結果

### 1. 学年別サンプル問題セットの生成
- 算数: [1年生(たし算・ひき算)](./samples/sansu/grade1_sample.md) / [2年生(筆算・かけ算)](./samples/sansu/grade2_sample.md) / [3年生(わり算)](./samples/sansu/grade3_sample.md) / [5年生(分数・割合)](./samples/sansu/grade5_sample.md)
- 国語: [1年生(ひらがな・かたかな・読解)](./samples/kokugo/grade1_sample.md) / [2年生(漢字・句読点・読解)](./samples/kokugo/grade2_sample.md) / [3年生(漢字・文法)](./samples/kokugo/grade3_sample.md) / [5年生(敬語・読解)](./samples/kokugo/grade5_sample.md)

いずれも、学年別の到達目標・数値範囲・漢字配当表を指定するプロンプトのみで、
学年を超える概念(未習の解法・漢字・文法用語)を使わない問題セットを生成できた。
1〜5年生の間で数値の抽象度・思考ステップ数・使用可能な漢字に明確な差が生まれており、
**学年に応じた難易度調整はプロンプト内の条件指定だけで機能する**ことを確認した。
特に低学年(1・2年生)では「漢字を使わない/学年配当漢字に限定する」という制約を
プロンプトで明示しないと、モデルが未習の漢字を混ぜてしまうケースが見られ、
制約の明示が低学年ほど重要になることが分かった。

**受け入れ条件との対応: 満たした。**

### 2. 難易度の妥当性
各問題に対応する学習指導要領の項目(例:「A(3) 除法」「C(1) 精査・解釈」)を
生成結果自体に明記させることで、単元逸脱の有無を人手でレビューしやすい形にした。
今回生成したサンプルはレビューの結果、学年水準を逸脱する内容は見られなかった。

一方で、選択式・計算問題は正誤判定が容易だが、記述式問題(例: 国語5年生の読解記述問題)は
自動採点が難しく、**採点用ルーブリックの別途生成**が必要になることが分かった
([国語5年生サンプルの問題4](./samples/kokugo/grade5_sample.md)参照)。

### 3. 苦手分野分析→類題生成のプロトタイプ
[`samples/weakness-analysis/sample_case1.md`](./samples/weakness-analysis/sample_case1.md) にて、
異分母分数の計算でつまずいた児童の解答結果から、
- 誤答を「通分をせず分母・分子をそのまま演算している」というつまずきパターンに分類
- 同じ単元・同程度の難易度で数値のみ変えた類題を3問(段階的な難易度)生成

というフローが、プロンプト設計のみで一通り動作するプロトタイプとして成立することを確認した。

重要な発見として、**最終解答の正誤だけでは誤りの型を特定できず、
選択した誤答内容や途中式(記述式の場合)まで入力する必要がある**ことが分かった。
これはアプリ側の解答UI設計(途中式の入力を促す、選択式なら誤答パターンを設計時点で分類しておく等)に
直結する要件となる。

**受け入れ条件との対応: 満たした。** (ただし精度向上には解答UI側の入力設計が前提条件になる)

### 4. プロンプト設計 vs RAG の判断

| 観点 | プロンプトのみ | RAG(指導要領/教科書データ参照) |
|---|---|---|
| 学年別単元・到達目標の反映 | 十分機能した(モデルの一般知識で概ねカバー) | より厳密な文言・出題範囲の一致は可能 |
| 漢字配当表など詳細な制約 | プロンプトへの明記で概ね遵守された | 配当表を検索対象にすれば取りこぼしをさらに低減できる |
| 教科書会社ごとの表記・進度差 | 反映できない(モデルの一般知識ベースのため) | 教科書別データがあれば対応可能 |
| 実装コスト | 低い(プロンプトテンプレートのみ) | 高い(指導要領/教科書データの整備・検索基盤が必要) |

**結論: Phase 0時点ではプロンプト設計のみで採用する。**
理由:
- 今回検証した範囲(小学校国語・算数の主要単元)では、プロンプトに学年・単元・到達目標・
  漢字配当表を明記するだけで、学年水準を逸脱しない実用的な品質の問題が生成できた
- RAGが真に必要になるのは「教科書会社ごとの進度差への対応」「指導要領の正確な文言引用が
  求められる場面」などであり、これはMVP段階では優先度が低い
- 将来的に教科書対応や出題範囲の厳密化が要件になった時点で、
  指導要領テキスト・漢字配当表をベクトル検索できるRAG基盤への移行を検討する
  (移行コストを下げるため、プロンプトの「学年/単元/到達目標」パラメータ構造はそのままRAGの
  検索クエリ構造に転用できる設計にしてある)

### 5. 学期(時期)に応じた問題生成の検証

同じ学年でも1学期・2学期・3学期で学習している単元は異なる(例: 算数3年生では
1学期に「かけ算の筆算」、2学期に「わり算(あまりあり)・小数・分数」、
3学期に「□を使った式・二等辺三角形」を学ぶ、など)。この時期のズレに対応できるかを検証するため、
[`term-prompt.md`](./prompts/term-prompt.md) というプロンプトテンプレートを追加し、
算数3年生・国語3年生それぞれについて1〜3学期のサンプル問題を生成した。

- 算数3年生: [1学期](./samples/sansu/by-term/grade3_term1_sample.md) / [2学期](./samples/sansu/by-term/grade3_term2_sample.md) / [3学期](./samples/sansu/by-term/grade3_term3_sample.md)
- 国語3年生: [1学期](./samples/kokugo/by-term/grade3_term1_sample.md) / [2学期](./samples/kokugo/by-term/grade3_term2_sample.md) / [3学期](./samples/kokugo/by-term/grade3_term3_sample.md)

**分かったこと:**

1. **学習指導要領そのものには学期別の指定がない。**
   指導要領は学年単位の到達目標を定めているだけで、「何月にどの単元を教えるか」は
   教科書会社ごとの年間指導計画によって決まる。そのため学期対応の生成は、
   指導要領の知識だけでは不十分で、「一般的な年間指導計画の順序」という
   別の知識をプロンプトに追加する必要があった。
2. **一般的な年間指導計画の順序であれば、プロンプトのみでも学期ごとの単元の切り分けができた。**
   1学期(前学年の復習+基礎)→2学期(新概念の導入)→3学期(抽象化・総合化)という
   学期を追った難易度・抽象度の上昇が、算数・国語ともに自然に再現された
   (例: 国語3年生3学期の[問題3](./samples/kokugo/by-term/grade3_term3_sample.md)では、
   1学期の「観察記録文」と2学期の「比較・分類の説明文」を明示的に参照する「まとめ」問題が
   生成でき、学期をまたいだ既習内容の参照にも対応できる可能性を確認した)。
3. **ただし教科書会社ごとの単元順序の違いには対応できない。**
   単元の配置時期(例: ローマ字を1学期に教えるか2学期に教えるか)は教科書会社によって
   数ヶ月単位でずれることがあり、モデルの一般知識だけでは特定の教科書・学校のペースには
   完全には一致しない。各サンプルの末尾に「※教科書会社によって順序が異なる場合がある」と
   注記が生成されており、モデル自身もこの限界を認識できていた。

**結論:** 学期対応も基本的にはプロンプト設計(一般的な年間指導計画の知識をプロンプトに埋め込む)
で実用レベルのプロトタイプが成立する。ただし、特定の学校・教科書に完全に合わせた時期別出題を
将来要件とする場合は、その学校で採用している教科書会社の年間指導計画表をデータとして持たせる
(RAGまたは設定ファイル形式での参照)ことが必要になる。これは[4章](#4-プロンプト設計-vs-rag-の判断)の
結論(Phase 0ではRAG不要)を変えるものではないが、**RAG導入の優先候補は「学年別到達目標」より
「教科書別の年間指導計画」である**という知見が今回新たに得られた。

## 今後の課題(Phase 1以降への申し送り)
- 記述式問題の自動採点(ルーブリック生成 or 意味的類似度判定)の設計
- 解答UIにおける「誤答内容・途中式の取得」の仕様化(苦手分野分析の精度に直結)
- 対象学年・教科の拡大(中学年以降、理科・社会等)時にRAG移行が必要かの再評価
- 特定の教科書・学校のペースに合わせた学期別出題が要件化した場合、
  教科書会社ごとの年間指導計画表をデータ化してRAGまたは設定ファイルとして参照する仕組みの検討
